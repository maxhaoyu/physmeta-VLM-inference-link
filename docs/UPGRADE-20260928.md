# 队列与 Windows 节点配套升级

本版本在 main 的模型预热、异常退出码和单框容错基础上，补齐心跳与结果回传。Windows 节点显示 `minimal-1.1.0`。

## 运行流程

启动监控 → 预热模型 → 领任务并声明支持心跳 → 立即上报 processing → 每 15 秒续期 → 下载、推理、回传 → 收到成功确认后清理本地任务。预热与首单串行，避免 YOLO 重复加载。

下载/回传临时断网默认最多重试 300 秒，重传同一结果包不重新推理。服务器丢失成功回复时，字节相同的重试返回成功；不同结果不能覆盖完成记录。租约失效时保留本地文件并停止发布。长时间掉线超过租约后由队列重新派发，不承诺跨进程断点续算。

## Windows 启动文件

Git 的 `node/start-node.bat` 调用 `launch_node.py`，后者选择现有 bubble_src 所在项目的 `.venv`，或配置 `python_executable` / 环境变量 `PHYS_META_PYTHON` 指定的解释器。不会安装依赖、更新 CUDA、下载模型或改令牌。

- `start-node.bat --check`：只验证配置、节点版本和 CUDA，不领任务。
- 双击 `start-node.bat`：持续运行。正常退出不重启；认证/配置错误停止；未预期崩溃（退出码 2）间隔 5 秒自动重启，最多 10 次。
- `start-node.bat` 启动前先检查同目录的 `inference-node.json`。缺少时会用中文说明当前目录不是已配置节点，不再显示 Python 文件不存在错误。
- BAT 不是完整程序，不能只复制 BAT。应使用配套更新 ZIP，含 agent、启动器和相同版本的 bubble_ocr Python 源码。

真实的 `inference-node.json` 含节点令牌、节点身份和本机模型/环境路径，不得上传 Git 或打入公开 ZIP。公开包只含无凭据的 `inference-node.example.json`；升级已有节点时，更新器直接保留原节点目录中的真实配置。

## 拷贝更新包

1. 关闭旧节点窗口；如果配置了任务计划，先暂停自动启动。
2. ZIP 解压到一个临时目录，不要直接解压到现有节点目录。
3. 解压目录正常只显示 `升级现有节点.bat`。双击它，输入原节点目录；直接回车时默认使用 `C:\PhysMetaInference-ocr`。隐藏的 `.physmeta-update` 是经校验的内部程序目录，不要单独运行或移动其中的文件。
4. 更新器校验包内 SHA-256，按旧 inference-node.json 找到 bubble_src，先备份被替换代码到 `code-backups`，再安装程序。账号配置、令牌、环境、模型、原任务目录保持原样。已有节点进程仍运行时拒绝更新。
5. 到原节点目录运行 `start-node.bat --check`；成功后双击 `start-node.bat`。保留原任务计划时须让它调用新启动器，不能再指向其他旧目录。
6. 完成一张合成图纸识别，确认收到结果后再恢复常用任务。

## 服务器兼容升级

服务端与 Windows 并非必须在同一秒更新。新节点领单明确声明 heartbeat=true；旧节点未声明则不自动超时回收，既有队列记录也默认不回收。这样旧 Windows 未更新时仍可运行；也意味着旧节点卡死仍需人工检查。

滚动升级期服务器设置 `INFERENCE_LEGACY_NODE_COMPAT=1`：仅对未声明心跳的旧任务允许缺少结果 SHA 头（与旧线上行为一致），有 SHA 头仍校验，新节点必须校验。Windows 全部升级验收后设为 0 恢复严格模式。

本次部署设 `INFERENCE_RETENTION=0`，关闭队列自动清理，保留旧历史。非零为已结束任务文件/记录的保留秒数，默认代码值为 7 天。未建立历史归档确认前不要启用清理。

队列升级先用 SQLite backup API 和文件快照备份；旧图片、结果、凭据、模型不入 Git。数据库新增列保留旧记录。只替换 inference-queue 和 yolobubble，不重建其他业务服务。

## 验证范围

纯 CPU 的真实 HTTP 集成测试模拟长 GPU 任务、多节点抢单、断网、成功回包丢失、旧租约回传和新旧节点兼容。yolobubble 另外验证单框失败需复核、PDF、多页历史和两个队列版本的协议。

这些测试不等于真实 Windows CUDA 识别质量验收；Windows 可操作后仍须执行第 6 步。
