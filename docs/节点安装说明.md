# Windows 推理节点安装说明（整链路 · bubble-ocr 版）

> 前提：客户 Windows 有 NVIDIA 独立显卡（8G+）+ CUDA，**只做推理**。
> 链路：YOLO 检测 → RapidOCR 识值 → 格式规范化 → VLM 兜底 → 一致性仲裁，全部在 Windows 本地跑。
> 服务器只负责收图纸、存结果、下发任务。图纸不出客户内网。

## 一、目录准备

在 Windows 本地磁盘建立 `C:\PhysMetaInference`，放入：

```
C:\PhysMetaInference\
├── agent.py                       ← 精简版节点端（本方案 node/agent.py）
├── inference-node.json            ← 节点配置
├── vlm_fallback_windows.py        ← Windows 版 VLM 后端（替换 mlx）
├── requirements-windows.txt       ← 依赖清单
└── bubble-ocr-app\                ← 你的识值代码（整个仓库拷过来）
    ├── src\bubble_ocr\            ← 核心包（detect/recognize/pipeline/...）
    ├── models\
    │   ├── yolo\cv88-baseline-epoch11.pt   ← YOLO 权重
    │   ├── vlm\                          ← VLM 权重（Windows 能跑的 HF 格式）
    │   └── adapters\                     ← VLM adapter（如有）
    └── ...
```

## 二、Python 环境 + 依赖

```powershell
# 1. 建虚拟环境（推荐 Python 3.10/3.11）
python -m venv C:\PhysMetaInference\.venv
C:\PhysMetaInference\.venv\Scripts\activate

# 2. 装 CUDA 版 torch（按显卡驱动选 index-url，CUDA 12.1 为例）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# 3. 装主线 + VLM 依赖
pip install -r C:\PhysMetaInference\requirements-windows.txt
```

## 三、VLM 后端切换（关键步骤）

`bubble-ocr-app` 自带的 `vlm_fallback.py` 用 `mlx-vlm`（macOS 专属），Windows 跑不了。
两种改法，选其一：

### 改法 A（推荐）：直接覆盖

把本方案的 `vlm_fallback_windows.py` 覆盖到：
`bubble-ocr-app\src\bubble_ocr\vlm_fallback.py`

两者接口完全一致（`read_box` / `fallback` 签名相同），其余代码不用动。

### 改法 B：按平台 import（更干净，适合长期维护）

在 `pipeline.py` 顶部按 `sys.platform` 选择：

```python
import sys
if sys.platform == "win32":
    from . import vlm_fallback_windows as vlm_mod
else:
    from . import vlm_fallback as vlm_mod
```

## 四、VLM 模型权重

macOS 上的 `MiniCPM-V-4.6-5bit`（mlx 格式）Windows 读不了，需要换成 HuggingFace 格式的权重。

基座模型（部署用，8G 显存轻松跑，1.3B）：
- **MiniCPM-V-4.6-hf-ra600**（已 merge checkpoint-600 增量，约 2.6GB）

> ⚠️ **必须挂 ra600 基座**，不能挂原始 `openbmb/MiniCPM-V-4.6`。
> `checkpoint-150-best` 是在 ra600 基座上训练的（见其 `adapter_config.json` 的
> `base_model_name_or_path`），挂原始 hf 会错位。详见 `docs/MODEL_VERSION.md`。

下载到 `models\vlm\`，在 `inference-node.json` 的 `vlm_model` 指向它。

### LoRA adapter（重训产物）

macOS 的 train3 LoRA 是 mlx 格式，Windows 读不了（mlx 的 `linear_attn.*` 层 peft 无法映射）。
因此用 **ms-swift 在 Windows 重训** peft 格式 LoRA，训练脚本与数据在 `bubble-ocr-app` 仓库里：

- 训练脚本：`bubble-ocr-app/scripts/train_swift_windows.py`
- 验证脚本：`bubble-ocr-app/scripts/eval_swift_lora_windows.py`
- 训练数据：`bubble-ocr-app/data/vlm_train3/swift/{train,val}.jsonl`（6000 条，随 git 同步）

当前部署用 **`checkpoint-150-best`**（20MB，`adapter_config.json` + `adapter_model.safetensors`
+ `additional_config.json` + `README.md`），放到 `models\adapters\checkpoint-150-best\`，
在配置里把 `vlm_adapter` 指向它。`vlm_fallback_windows.py` 会通过 `adapter_path` 自动挂载
peft LoRA；挂载失败则自动降级为裸模型（不报错）。

## 五、配置

复制 `inference-node.example.json` → `inference-node.json`：

```json
{
  "server": "https://app.physmeta.cn",
  "token": "服务器下发的节点令牌",
  "node_id": "windows-inference-01",
  "root": "C:\\PhysMetaInference",
  "bubble_src": "C:\\PhysMetaInference\\bubble-ocr-app\\src",
  "jobs_root": "C:\\PhysMetaInference\\inference-jobs"
}
```

## 六、运行

```powershell
# 手动跑一次验证（领一个任务处理完就退出）
C:\PhysMetaInference\.venv\Scripts\python.exe agent.py --config C:\PhysMetaInference\inference-node.json --once

# 长期后台运行
C:\PhysMetaInference\.venv\Scripts\python.exe agent.py --config C:\PhysMetaInference\inference-node.json
```

## 七、开机自启（Windows 任务计划）

管理员 PowerShell：

```powershell
$action = New-ScheduledTaskAction -Execute "C:\PhysMetaInference\.venv\Scripts\python.exe" `
  -Argument "C:\PhysMetaInference\agent.py --config C:\PhysMetaInference\inference-node.json"
$trigger = New-ScheduledTaskTrigger -AtStartup
Register-ScheduledTask -TaskName "PhysMetaInferenceNode" -Action $action -Trigger $trigger -RunLevel Highest
```

## 八、验证链路

1. 服务器端启动，客户浏览器走 bubble-ocr 的 `POST /upload` 传图纸。
2. 服务器把任务放入队列，节点 `claim` 领到 → 下载 → YOLO+OCR+VLM → 回传 result.json。
3. 前端轮询 `GET /api/inference/jobs/{id}`，状态 `pending → claimed → processing → done`。

## 九、注意事项

- 节点只主动出站，客户防火墙/NAT 无需开入站端口。
- VLM 模型缺失时，节点自动降级为纯 OCR 主线（不报错），保证链路可用。
- 基座用 MiniCPM-V-4.6（1.3B），8G 显存 FP16 即可，无需量化。
- 首次推理会加载模型（几十秒级），后续单进程内复用（agent 常驻，模型只 load 一次）。
